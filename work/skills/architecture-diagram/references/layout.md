# Layout and visual contract

本文件约束相对关系、文字排布、连接和最小间距，不锁定示例坐标、列数或画布比例。`MUST` 为约束，`SHOULD` 为布局建议；数值是统一基线，不是把所有内容压进最小空间的上限。

## Output

- **MUST**：独立、静态、全英文 HTML；只显示标题、图和必要图例。无工具栏、缩放控件、主题切换、详情面板、PPT / 幻灯片分支。
- **MUST**：根据内容确定画布，不能强制 16:9 / 4:3 或一屏容纳。节点数不是画布上限或强制拆图阈值；可用宽度、文字长度、边界与路径共同决定布局。内容过密时重排、扩展原图或拆图，不缩小单个节点逻辑字号，不以错误分层换取紧凑。
- **MUST**：使用公共 renderer 和 tokens；不要为某个示例复制修改 CSS 或箭头样式。`original` 与 `article` 的尺寸处理按下节分别验收，不能用一个模式的通过结果替代另一个模式。
- **MUST**：图例只列本图实际使用的颜色 / 线型语义，无教学口号、左侧装饰编号或长段免责声明。

## Presentation and available width

先记录目标页面可用内容宽度、浏览器视口与交付模式，再安排布局。可用宽度是图实际得到的空间，已经扣除文章栏、父容器 padding 和边框；不等于屏幕宽度。独立图可以具有较大的内容画布，文章总览则需要在约定的文章宽度下保持可读。

| 模式 | 尺寸行为 | 验收边界 |
| --- | --- | --- |
| `original`（默认） | 保留逻辑尺寸，图形不整体缩放；大图允许按原始尺寸滚动查看 | 逻辑字号、几何与局部可读性；滚动和原始画布尺寸在交付时说明 |
| `article` | 统一按可用宽度适配，比例不大于 1，不因父容器较宽而放大 | 实际显示字号达到 `theme.presentation` 阈值，无横向裁切或依赖横向滚动阅读；iframe 高度随内容同步 |

- **MUST / original**：禁止用 CSS `zoom`、transform 或外层缩放把逻辑 24px 节点名称压小后仍声称原图字号合格。
- **MUST / article**：只使用公共 renderer 提供的宽度适配；不得叠加文章 CSS 缩放，也不得为过关降低字号阈值。实际字号要计入 SVG 与父级变换造成的显示比例，不能只读 `font-size: 24px`。
- **MUST / article**：节点主名称实际显示至少 18 CSS px，标题、副标题、层名、标签、图例等其他文字至少 14 CSS px。统一阈值为 `assets/theme.json` 中的 `presentation.minNodeFontSize` / `minTextFontSize`；模型不覆盖它们，截图的设备像素倍率也不替代 CSS 像素判断。
- **MUST / article**：不足以同时满足宽度与字号时，先减少无关内容、调整层内排列、换行和通道；仍不适合则提供文章可读总览及对应详图。两张图仍需保留各自参与的真实边界和技术关系，不能为紧凑制造错误直连。
- **MUST**：所承诺的移动端宽度也要独立检查。低于阈值应明确记录该宽度失败，或另提供在该宽度合格的总览；不能以“可点击独立详图”把当前不可读的图记作通过。

文章高度由内容决定，可以随页面正常向下滚动；文章模式不要求整图在一个视口高度内出现。原图链接可以补充细节，但不替代文章图本身的可读性验收。拆分依据是读者需要和实际布局，不是预设的节点数量。

## Text and spacing tokens

本 skill 借鉴 Google / Material 的简洁排版，不宣称符合某个官方 Google 架构图标准。公共样式参数保存在 `assets/theme.json`；统一使用 CSS px / SVG 逻辑像素，不混用 Android dp。标题行数变化时按实际文本测量计算高度。

- **MUST**：构建时内嵌固定版本的 Roboto（400 / 500 / 700）与 Roboto Mono（400 / 700），不访问远程字体，不依赖本机恰好安装的字体。字体来源、版本和许可证随资源保留。
- **MUST**：普通文字使用 Roboto；`library` 与 `kernel-interface` 的节点主名称使用 Roboto Mono。副标题或连线标签若完整内容是设备路径或函数签名，也使用 Mono；不因混合说明中出现代码就把整段变成等宽。类名保持无衬线，不因名称长而缩字。
- **MUST**：实际加载所需字体后才进行换行、文本测量和绘制；加载失败明确报错，不用后备字体测量后再静默替换。现代系统字体栈只是防御性后备，不是离线字体资源的替代品。

| 项目 | 基线 |
| --- | ---: |
| Figure title | 36 |
| OS / VM / domain title | 30 |
| Layer / process title | 27 |
| Node name | 24 |
| Node / container subtitle | 18 |
| Edge label | 19.5 |
| Body text | 21 |
| Legend text | 18 |
| Container content padding | ≥ 16 |
| Peer node gap | ≥ 24 |
| Parallel OS / VM gap | ≥ 40 |
| Parallel line center distance | ≥ 12 |
| Line clearance from unrelated text / nodes | ≥ 8 |
| Final straight segment before arrow | ≥ 16 |

字号以 Block 主名称 24px 为统一逻辑基准；HTML 与软件架构 draw.io 共用这套建模参数。`original` 保持原始显示尺寸；`article` 可由公共展示层统一适配，但必须通过上一节的实际字号检查。不要改小模型或 CSS 中的逻辑字号来塞入文章栏。调整公共字号时同步检查节点、header、标签与通道的真实文本空间，必要时重排或拆图，不改技术层次与连接关系。

增加线路和长标签时扩宽通道。无副标题时不预留空行；不为填满节点添加无意义文字。

统一圆角为 4 / 8 / 12：连线标签与图例色块 4，普通节点及子容器 / 进程容器 8，Domain 容器与外层 Shell 12。内存仍保留堆叠形状；圆角不能抹去资源类型的区别。

## Content-driven dimensions

- **SHOULD**：按实际字体测量名称，节点宽度从文本宽度加两侧内边距开始；高度从实际行数及上下内边距开始，再为多入口、标签或同组对齐增加空间。不要把某个旧图的 420×110 等大节点尺寸当成模板默认值。
- **SHOULD**：容器从 header、实际子元素边界、必要通道和 padding 向外计算；没有内容或路径用途的大片空白应收紧。画布贴合最外层边界与必要留白，不预先分配巨大画布再填内容。
- **SHOULD**：在同样的技术关系下比较并排与层内纵排；以目标宽度下可读、线路易追踪为依据选择。紧凑性是目视复核项，不采用统一“空白率”自动判定所有技术图。

## Containers

- **MUST**：标题左上对齐，副标题在其下；标题组占用独立 header，子节点和子容器从其下开始。不得把标题压在边框上或另开左侧编号栏。
- **MUST**：header 高度由标题 / 副标题行数、字体和留白计算；换行后同步下移内容区域。内边距、内容、走线空间共同决定容器尺寸。
- **MUST**：标题文字及其 8px 安全区不可穿线。header 内不能放子节点；header 中专门预留的空白通道允许跨层连线通过。不得把整个 header 误判为不可穿越的实心障碍。
- **MUST**：同排同类容器的标题基线及内容起始线对齐；节点不能越出父容器或侵占父 header。包含只表达归属，不代表调用。
- **MUST**：层带与进程边界具有不同意义。层与进程同时展开时，保留真实归属，不能用视觉嵌套暗示库运行于错误进程。
- **SHOULD**：同层组件对齐、间距均衡；进程可并列或在本层内上下展开。为主调用路径和跨层边保留走线通道。

## Nodes

- **MUST**：主名称居中，副标题紧随其下；整个文字组在节点内部垂直居中。主名称通常 1–2 行，复杂真实名称可在合理分隔处增加行数并扩大节点。
- **MUST**：真实名称不截断、不加省略号、不擅自缩写、不局部缩字；长名称先加宽再换行。不得拆改文件名后缀、路径和类名拼写来假装适配。
- **SHOULD**：同组节点尽量等宽；名称或语义差异明显时允许不同宽度。所有节点不必相同尺寸。
- **MUST**：内存资源用堆叠矩形，物理硬件与软件具有可分辨样式；固件不是硬件寄存器。配置但未启用对象使用中性虚线边框，并保留必要英文状态。

## Macro layout

- **MUST**：先依据 [modeling.md](modeling.md) 锁定部署骨架和技术角色，再分配坐标。布局优化可以调整尺寸、间距、层内组件次序和通道，不能改变承载关系或大层次。
- **MUST / virtualized-soc**：SoC 外框包含左侧可选 TEE、右侧并列 VM、VM 下方 Hypervisor 和最下方共同 Hardware；独立 MCU 在 SoC 外侧并列，顶底对齐 SoC。VM 顶齐，TEE 如参与顶齐 VM、底齐 Hypervisor；Hardware 横向覆盖 TEE 与 VM。
- **MUST**：同一 OS / VM 的大层次自上而下；层内布局根据粒度和真实依赖决定。大层次不能为了走线方便而上下倒置。
- **MUST**：Hypervisor 层带对齐实际承载 VM 的整体左右外边界，覆盖中间间隙，不覆盖独立域。数据线可以经过层带空白通道，不因此增加端点。
- **MUST**：资源与硬件按真实交接链定位，遵守 [modeling.md](modeling.md) 的输入 / 输出规则。
- **MUST**：先部署容器，再技术层与进程，再节点，最后端点、通道与标签。不能围绕一条业务流程线反向构造软件层或让 MCU 脱离同排部署骨架。
- **SHOULD**：复杂路径触发层内重排、扩宽通道或扩展画布，而不是连续加折线补救。仍无法清晰表达时拆分补充视图，保留主图的关系。

## Edges

### Stable semantics

节点用途配色不改变线型语义。箭头、标签及真实分支点与连线同色。

| 关系 | 色值 | 线型 / 宽度 |
| --- | --- | --- |
| Dependency | `#5f6368` | Thin solid / 1.5 |
| Call / control / IPC | `#356dc9` | Solid / 1.8 |
| Data / pixels | `#237a44` | Solid / 2.6 |
| Notification / doorbell / IRQ | `#356dc9` | Dotted `3 5` / 1.8 |
| Configuration / allocation | `#5f6368` | Dashed `6 5` / 1.5 |

`MUST`：配置线不表示每次数据必经路径。控制和数据共享端点不等于相同传输机制。

箭头、跨线弧留白、分支点和图例从同一组线型参数派生；调整线宽后一起复核，不单独覆盖某张图的 CSS。

### Endpoints and routing

- **MUST**：水平 / 垂直正交走线；跨线弧是局部例外。起始段垂直离开源边界，末段垂直进入目标边界，箭头贴边且不侵入文字。
- **MUST**：某条节点边只有一个入口 / 出口时居中。多路输入分配独立入口，主链优先居中，其余按来向排序，不能在目标前无必要地交换左右位置。
- **MUST**：不堆叠箭头，不将不同接口 / 机制合并为一条公共线。真实分支才共享路线并使用实心连接点。
- **MUST**：不穿无关节点、标题文字及标签，不与容器边框长距离重合。跨越容器边界本身不代表调用容器。
- **SHOULD**：从朝向对端的边出入，优先最短清晰通道，避免背向绕行和反复折返。两端属于同一容器时优先在容器内走线；空间不足先调整布局。
- **SHOULD**：达到 5 个折点触发布局复核，不是绝对禁令。只有存在技术 / 几何原因并记录理由时才保留复杂绕线。
- **MUST**：先用入口排序、组件对齐和通道规划消除非必要交叉，再对不可避免的非连接交叉绘制跨线弧。弧不能撞到拐点、标签或邻线；真实连接必须有实心点。
- **Editing / MUST**：端点随节点边界计算，移动组件后重新检查折点、入口顺序、标签和交叉；不能只检查箭头是否仍能连上。

### Labels

- **MUST**：标签水平，位于其所属直线段旁并保持关联清楚；避开箭头、拐点、分支点和跨线弧。
- **MUST**：不遮挡线路、容器标题或节点；必要时增加直线段空间或调整通道，不把标签漂在远处。
- **SHOULD**：只写必要接口、协议、数据或操作名；图例已充分表达的简单关系不必每条重复标注。

## Purpose-specific node colors

- **Technical (default)**：使用模板的中性软件色、低对比容器和硬件 / 内存灰；不要求来源数据。
- **Origin**：`oem` 蓝 `#4285F4`、`native` 绿 `#34A853`、`vendor` 黄 `#FBBC04`；来源未知中性。节点文字使用深色，容器不使用来源色。
- **Responsibility**：模型声明单一责任维度及本图责任方 → 颜色映射；每种颜色只表示一个已使用责任方，图例必须说明该维度。默认类别映射为 OEM 蓝、Tier1 黄、SoC Vendor 紫、OS Vendor 绿、Other 青；多个同类别责任方使用不同的预置 paletteKey，不能直接拿 origin 字段代替责任证据。

责任模式调色板：`blue #4285F4`、`green #34A853`、`amber #FBBC04`、`purple #A78BFA`、`cyan #38BDF8`、`orange #FB923C`、`pink #F472B6`、`indigo #818CF8`。来源模式仍只使用其来源映射，不借用责任色表达未知含义。

节点颜色和线条颜色处于不同视觉通道，图例分别说明。不得引入按 OS 变色的边框、表示混合来源的渐变或随意借用旧参考图配色。
