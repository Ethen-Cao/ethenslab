网络 Response 已经到达 someipd；失败的是 someipd 向 PVM 本地业务端点投递响应。它不是“向 Android 网卡发包超时”。

为什么返回 BASE_E_TIMEOUT

netsock_readytosend(fd, us) 检查的是 fd 在指定时间内是否可写。

writefds + select()PVM local fd
FD_ZERO(&wfds);
FD_SET(fd, &wfds);

ret = select(fd + 1,
             NULL, &wfds, NULL, &tout);

if (ret > 0) return BASE_E_OK;
if (ret < 0) return ...;
return BASE_E_TIMEOUT;  // ret == 0
ret > 0发送缓冲区可写
ret == 0等待期内一直不可写
ret < 0EBADF 或其他系统错误
  • 1
    本地发送队列积压AF_UNIX send buffer 被突发 RPC Response 填满。
  • 2
    coreservice 未及时读取业务线程阻塞、调度延迟或回调处理过慢。
  • 3
    瞬时系统性卡顿多个 VLAN 在相近时间报错，更值得检查公共消费者和 CPU 调度。

如何理解 Android 网络正常

网络诊断与本次错误并不矛盾，因为它们观察的不是同一段链路。

  • Android 诊断：isNormal=true、hasProblem=0、ipv4Available=1、目标丢包率 0%。说明被检测的 GVM IP 网络当时正常。
  • 本次错误：someipd 对本地 AF_UNIX fd 做可写检查时超时，直接故障域位于 PVM 内部。
  • 边界：这不能证明整车所有网络在任何瞬间都绝对正常，但足以说明该条 BASE_E_TIMEOUT 不是 Android 丢包日志。
现场模型：PVM someipd × 6 · coreservice · VIPC/VSOCK · GVM Vehicle HAL 诊断重点：先检查 coreservice 消费速度、Unix socket 队列和线程调度，再扩大到物理网络。
